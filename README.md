# InSales (или другая платформа) → Yandex Cloud → Telegram Orders

Автоматическая отправка уведомлений о заказах из InSales (или другой платформы, где можно добавить email для отправки копии о новом заказе) в Telegram через Yandex Cloud.

Проект появился из практической проблемы: приложение InSales было удалено из App Store, а push-уведомления о новых заказах перестали стабильно приходить даже на телефонах, где приложение уже было установлено. Для интернет-магазина это критично: если менеджер поздно увидел заказ, клиент может уйти к конкурентам.

Решение - отправлять уведомления о новых заказах напрямую в Telegram.

---

## Что делает проект

Когда появляется новый заказ, магазин отправляет email-копию заказа на специальный адрес Yandex Cloud. Далее  разбирает письмо, достаёт данные заказа и отправляет аккуратное сообщение в Telegram. Уведомление приходит через 5-10 секунд после оформления заказа.

Базовая схема:

```text
InSales
  ↓ email-уведомление о заказе
Yandex Cloud Email Trigger
  ↓
Cloud Function
  ↓
Telegram
```

В расширенной версии добавляются кнопка принятия заказа, хранение статуса в YDB и повторное напоминание, если заказ никто не взял в работу на протяжении заданного времени.

---

## Зачем это нужно

Основная задача - не пропускать новые заказы.

Telegram обычно уже открыт у менеджеров, уведомления приходят быстро, а сообщения можно отправлять сразу в общий рабочий канал. Это удобнее, чем зависеть от мобильного приложения InSales, почты или ручной проверки админки.

Проект подходит, если нужно:

- получать новые заказы из InSales в Telegram;
- быстро видеть номер заказа, клиента, телефон, товары, сумму и ссылку на заказ в админке;
- понимать, кто из менеджеров взял заказ в работу;
- получать повторный пинг, если заказ не приняли за заданное время.

---

## Почему Yandex Cloud

### 1. Дёшево или почти бесплатно

Проект работает на serverless-сервисах Yandex Cloud, поэтому отдельный сервер держать не нужно. Оплата зависит от фактического использования: количества запусков функции, операций в базе, сообщений в очереди и исходящего трафика.

Для небольшого интернет-магазина нагрузка обычно маленькая: несколько, десятки или даже сотни заказов в день. В таком сценарии интеграция обычно остаётся очень дешёвой, потому что большая часть лимитов сильно выше реальной нагрузки магазина.

Например, один заказ в Pro-версии обычно создаёт несколько действий:

```text
1. Email Trigger запускает 
2. Функция отправляет уведомление в Telegram
3. Функция сохраняет заказ в YDB
4. Функция кладёт request_id в YMQ
5. Через 10 минут YMQ снова запускает функцию
6. Если заказ не принят — функция отправляет напоминание
```

На момент написания у Yandex s каждый месяц бесплатно доступны:

- **1 000 000 вызовов функций**
- **10 GB×hour выполнения функций**

Триггеры s отдельно не тарифицируются.  
Источник: [Yandex s pricing](https://yandex.cloud/en/docs/functions/pricing)

У Yandex Message Queue первые **100 000 запросов к очередям в месяц** также входят в бесплатный объём. В этом проекте в очередь отправляется маленький JSON только с `request_id`, поэтому одно сообщение обычно укладывается в один запрос.  
Источник: [Yandex Cloud Free tier](https://yandex.cloud/en/docs/billing/concepts/serverless-free-tier)

Для YDB Serverless бесплатно доступны:

- первые **1 000 000 операций в Request Units в месяц**
- первый **1 ГБ хранения данных в месяц**
- автоматические бэкапы за последние два дня

Источник: [Yandex Cloud Free tier](https://yandex.cloud/en/docs/billing/concepts/serverless-free-tier)

Примерная оценка для Pro-версии:

| Заказов в день | Заказов в месяц | Примерные вызовы функции в месяц | Комментарий |
|---:|---:|---:|---|
| 10 | ~300 | ~600–900 | С большим запасом ниже бесплатного лимита s |
| 100 | ~3 000 | ~6 000–9 000 | Всё ещё сильно ниже 1 000 000 вызовов функций в месяц |
| 500 | ~15 000 | ~30 000–45 000 | По вызовам функций запас остаётся большим |
| 1 000 | ~30 000 | ~60 000–90 000 | По s всё ещё ниже бесплатного лимита вызовов |

Расчёт приблизительный: в Pro-версии на один заказ обычно приходится 2–3 запуска функции:

```text
1. получение письма о заказе
2. клик по кнопке «Принять заказ», если менеджер нажал кнопку
3. проверка напоминания через YMQ
```

Lite-версия ещё дешевле, потому что в ней нет YDB, YMQ, кнопок и повторных запусков для напоминаний.

Итог: для типичного магазина с десятками или сотнями заказов в день такой сценарий обычно укладывается в бесплатные лимиты или стоит очень мало. Но точную стоимость всё равно лучше проверять в калькуляторе Yandex Cloud, потому что тарифы, регион, объём логов, хранение данных и исходящий трафик могут влиять на итоговую сумму.

## Две версии проекта

В проекте есть две версии: **Lite** и **Pro**.

### Lite - только уведомления

Подходит, если нужно просто получать уведомления о новых заказах или вы сами их обрабатываете, без штата менеджеров.

Схема:

```text
InSales email
  ↓
Yandex Email Trigger
  ↓

  ↓
Telegram message
```

В Lite-версии нет базы данных, очереди, кнопок и напоминаний. Это самый простой и быстрый вариант запуска.

### Pro - уведомления, кнопка и напоминание

Подходит, если нужно не просто получить уведомление, а контролировать обработку заказа.

Схема:

```text
InSales email
  ↓
Yandex Email Trigger
  ↓

  ├─ отправляет заказ в Telegram
  ├─ сохраняет заказ в YDB
  └─ ставит отложенное напоминание в YMQ
        ↓
     если заказ не принят — отправляет повторный пинг
```

В Pro-версии есть:

- кнопка **«Принять заказ»**;
- запись статуса `pending / accepted` в YDB;
- отображение, кто принял заказ;
- повторное напоминание, если заказ не приняли за 10 минут (или любого другого заданного времени);
- короткое reminder-сообщение без лишней информации.

## Шаг 0. Создание Telegram-бота и чата

Перед настройкой Yandex Cloud нужно подготовить Telegram-бота и чат, куда будут приходить уведомления о заказах.

---

### 0.1. Создать Telegram-бота

1. Откройте Telegram.
2. Найдите бота:

```text
@BotFather
```

3. Отправьте команду:

```text
/newbot
```

4. Укажите название бота.

Например:

```text
Order Alerts Bot
```

5. Укажите username бота.

Username должен заканчиваться на `bot`.

Например:

```text
order_alerts_demo_bot
```

После создания BotFather выдаст токен вида:

```text
1234567890:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Это токен Telegram-бота. Он понадобится для переменной окружения:

```env
TELEGRAM_BOT_TOKEN=
```

> Здесь вы сразу можете задать необходимое имя боту, настроить фотографию профиля.

---

### 0.2. Создать Telegram-чат или канал

Можно использовать:

- обычную группу;
- супергруппу;
- канал.

Для рабочих уведомлений удобнее использовать отдельный чат или канал, например:

```text
Заказы магазина
```

или:

```text
Order Alerts
```

---

### 0.3. Добавить бота в чат

Добавьте созданного бота в Telegram-чат или канал.

Если используется группа, достаточно добавить бота как участника.  
Если используется канал, бота нужно добавить как администратора.

Для Pro-версии желательно дать боту права:

```text
отправлять сообщения
редактировать сообщения
```

Право редактирования нужно, чтобы после нажатия кнопки бот мог заменить кнопку:

```text
✅ Принять заказ
```

на:

```text
✅ Принято: @manager
```

---

### 0.4. Как узнать ID чата

Чтобы отправлять сообщения в нужный Telegram-чат, нужно получить `chat_id`.

#### Вариант 1. Через getUpdates

1. Добавьте бота в нужный чат.
2. Напишите любое сообщение в этот чат.

Например:

```text
test
```

3. Откройте в браузере ссылку:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

Вместо `<TELEGRAM_BOT_TOKEN>` подставьте токен вашего бота.

Пример:

```text
https://api.telegram.org/bot1234567890:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/getUpdates
```

4. В ответе найдите блок `chat`.

Пример:

```json
{
  "message": {
    "chat": {
      "id": -1001234567890,
      "title": "Заказы магазина",
      "type": "supergroup"
    }
  }
}
```

Значение поля `id` — это и есть ID чата:

```text
-1001234567890
```

Сохраните ID, он понадобится при настройке функции. =

```env
TELEGRAM_CHAT_ID=-1001234567890
```

Если есть необходимость - создайте ещё один чат для тестов и также сохраните его ID:

```env
TELEGRAM_CHAT_ID_TEST=-1001234567890
```

---

### 0.5. Проверка отправки сообщения

После получения токена и `chat_id` можно проверить, что бот умеет отправлять сообщения.

Откройте ссылку:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/sendMessage?chat_id=<TELEGRAM_CHAT_ID>&text=Проверка
```

Если всё настроено правильно, в чат придёт сообщение:

```text
Проверка
```

После шага 0 должно быть готово:

```text
Telegram-бот создан
Бот добавлен в рабочий чат
Получен TELEGRAM_BOT_TOKEN
Получен TELEGRAM_CHAT_ID
Проверена отправка тестового сообщения
```

Для Pro-версии дополнительно проверьте, что бот имеет права редактировать сообщения в рабочем чате или канале. Это понадобится позже, когда будет добавлена кнопка **«Принять заказ»**.

Webhook на этом шаге настраивать не нужно. Он подключается позже, после создания , когда уже будет известен URL функции.

## Шаг 1. Подготовка Yandex Cloud

После создания Telegram-бота нужно подготовить Yandex Cloud. В нём будут работать , Email Trigger, а в Pro-версии дополнительно YDB и YMQ.

---

### 1.1. Создать аккаунт Yandex Cloud

Перейдите в консоль Yandex Cloud:

```text
https://console.yandex.cloud/
```

Если аккаунта ещё нет, создайте его и привяжите платёжный аккаунт.

> Для небольших нагрузок проект обычно стоит очень дёшево или укладывается в бесплатные лимиты, но платёжный аккаунт всё равно может понадобиться для активации облачных сервисов.

---

### 1.2. Создать облако и каталог

В Yandex Cloud используется такая структура:

```text
Облако
  └─ Каталог
       ├─ s
       ├─ YDB
       ├─ Message Queue
       └─ Service Accounts
```

Если облако и каталог уже есть, можно использовать существующие.

Если создаёте с нуля:

```text
Yandex Cloud Console
→ Создать облако
→ Создать каталог
```

Например:

```text
Облако: my-store-cloud
Каталог: production
```

или для тестов:

```text
Каталог: dev
```

---

### 1.3. Выбрать регион

Для этого проекта обычно используется регион:

```text
ru-central1
```

Он понадобится позже для переменной окружения:

```env
AWS_REGION=ru-central1
```

Эта переменная используется в Pro-версии для работы с Yandex Message Queue через AWS SDK.

---

### 1.4. Создать сервисный аккаунт

Сервисный аккаунт нужен, чтобы  могла обращаться к YDB, YMQ и другим сервисам Yandex Cloud.

Перейдите:

```text
Yandex Cloud Console
→ IAM
→ Сервисные аккаунты
→ Создать сервисный аккаунт
```

Название можно указать такое:

```text
order-alerts-functions-sa
```

или:

```text
telegram-orders-sa
```

---

### 1.5. Выдать роли сервисному аккаунту

Для Lite-версии достаточно прав на запуск функции через триггеры.

Для Pro-версии сервисному аккаунту нужны права на YDB, YMQ и вызов функций.

Рекомендуемый набор для Pro-версии:

```text
ydb.editor
ymq.writer
ymq.reader
serverless.functions.invoker
```

Что делают эти роли:

| Роль | Зачем нужна |
|---|---|
| `ydb.editor` | запись и чтение статусов заказов в YDB |
| `ymq.writer` | отправка отложенного сообщения в очередь |
| `ymq.reader` | чтение сообщения из очереди через триггер |
| `serverless.functions.invoker` | разрешение триггерам запускать  |

На этапе настройки можно временно использовать более широкую роль, например `editor`, но после проверки лучше оставить только необходимые права.

---

### 1.6. Создать статический ключ доступа для YMQ

Этот шаг нужен только для Pro-версии.

Yandex Message Queue совместима с AWS SQS API, поэтому для отправки сообщений в очередь через код нужны статические ключи доступа.

Откройте сервисный аккаунт:

```text
IAM
→ Сервисные аккаунты
→ order-alerts-functions-sa
→ Создать новый ключ
→ Статический ключ доступа
```

После создания Yandex Cloud покажет два значения:

```text
Access key ID
Secret access key
```

Их нужно сохранить для переменных окружения:

```env
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
```

> Важно: `Secret access key` показывается только один раз. Сохраните его сразу.

## Шаг 2. Подготовка YDB и YMQ

Этот шаг нужен только для **Pro-версии**.

Lite-версия не использует базу данных и очередь. Если вам нужны только простые уведомления в Telegram, этот шаг можно пропустить и сразу перейти к созданию функции (следующему шагу).

---

## Что будет создано

Для Pro-версии нужны два сервиса:

```text
YDB — хранение статуса заказа
YMQ — отложенное напоминание, если заказ не принят
```

Общая логика:

```text
Новый заказ
  ↓
 сохраняет заказ в YDB со статусом pending
  ↓
 отправляет сообщение в Telegram
  ↓
 кладёт request_id в YMQ с задержкой 10 минут
  ↓
Через 10 минут YMQ снова запускает функцию
  ↓
Если статус всё ещё pending — отправляется напоминание
Если статус accepted — ничего не происходит
```

---

## 2.1. Создать YDB

Перейдите в Yandex Cloud Console:

```text
YDB
→ Создать базу данных
```

Рекомендуемый тип:

```text
Serverless
```

Название можно указать, например:

```text
order-alerts-db
```

После создания базы нужно сохранить два значения:

```env
YDB_ENDPOINT=
YDB_DATABASE=
```

---

## 2.2. Где взять YDB_ENDPOINT и YDB_DATABASE

Откройте созданную базу YDB и перейдите в раздел подключения.

Там будет строка вида:

```text
grpcs://ydb.serverless.yandexcloud.net:2135/?database=/ru-central1/xxxx/yyyy
```

Для переменных окружения нужно разделить её на две части.

`YDB_ENDPOINT` — только адрес сервера:

```env
YDB_ENDPOINT=grpcs://ydb.serverless.yandexcloud.net:2135
```

`YDB_DATABASE` — путь к базе:

```env
YDB_DATABASE=/ru-central1/xxxx/yyyy
```

Важно: в `YDB_ENDPOINT` не нужно добавлять `?database=...`.

## 2.3. Создать таблицу в YDB

## Шаг 4. Подключение Email Trigger

На этом шаге подключаем почтовый триггер Yandex Cloud.

Email Trigger создаёт специальный технический email-адрес. Когда на этот адрес приходит письмо, Yandex Cloud автоматически запускает Cloud Function и передаёт в неё содержимое письма.

Именно через этот механизм заказ из InSales попадает в функцию.

---

## 4.1. Зачем нужен Email Trigger

InSales умеет отправлять email-уведомления о новых заказах. Мы используем это как источник данных.

```text
Функцию можно использовать и на других платформах.
Важно, чтобы там бала возможность отправки копии письма о заказе на указанную почту.
Ищите в настройках.
```

Схема:

```text
InSales
  ↓ email о новом заказе
Email Trigger Yandex Cloud
  ↓
Cloud Function
  ↓
Telegram
```

Email Trigger нужен и для Lite, и для Pro-версии.

---

## 4.2. Создать Email Trigger

Перейдите в Yandex Cloud Console:

```text
Cloud Functions
→ Триггеры
→ Создать триггер
```

В поле **Тип** выберите:

```text
Почта
```

Название триггера можно указать, например:

```text
order-mail-trigger
```

или:

```text
order-email-to-telegram
```

---

## 4.3. Выбрать запускаемый ресурс

В настройках триггера укажите:

```text
Запускаемый ресурс: Функция
Функция: order-mail-to-telegram
Тег версии функции: $latest
Сервисный аккаунт: order-alerts-functions-sa
```

Если функция названа иначе, выберите своё название.

Например:

```text
Функция: order-mail-to-telegram-pro
```

---

## 4.4. Настройки сохранения вложений

Если письма с заказами не содержат вложений, бакет выбирать не нужно.

Оставьте:

```text
Бакет: не выбран
```

Для этой интеграции вложения обычно не нужны, потому что данные заказа берутся из текста или HTML письма.

---

## 4.5. Настройки группировки сообщений

Рекомендуемые настройки:

```text
Размер группы: 1
Время ожидания: 0 секунд
```

Это значит, что каждое письмо будет сразу отдельно запускать функцию.

Для уведомлений о заказах это удобнее, чем группировать несколько писем в один запуск.

---

## 4.6. Настройки повторных запросов

На первом запуске можно оставить минимальные настройки:

```text
Количество попыток: 1
```

Так проще отлаживать ошибки и не получать дубли заказов при неправильной настройке.

После проверки можно увеличить количество попыток, например до:

```text
3
```

## 4.7. Dead Letter Queue

На старте DLQ можно не настраивать.

Оставьте:

```text
Очередь DLQ: не выбрана
```

DLQ имеет смысл добавлять позже, если нужно отдельно собирать письма, которые не удалось обработать.

## Шаг 5. Настройка Telegram webhook для Pro-версии

Этот шаг нужен только для **Pro-версии**.

В Lite-версии кнопок нет, поэтому Telegram webhook не нужен. Если вы используете только простые уведомления о заказах, этот шаг можно пропустить.

---

## 5.1. Зачем нужен webhook

В Pro-версии под сообщением о заказе есть кнопка:

```text
✅ Принять заказ
```

Когда менеджер нажимает эту кнопку, Telegram должен отправить событие на Cloud Function.

Для этого и нужен webhook:

```text
Нажатие кнопки в Telegram
  ↓
Telegram webhook
  ↓
Cloud Function
  ↓
YDB status = accepted
  ↓
Кнопка меняется на “✅ Принято: @manager”
```

---

## 5.2. Проверить, что функция публичная

Telegram должен иметь возможность вызвать Cloud Function по URL.

Откройте функцию:

```text
Yandex Cloud
→ Cloud Functions
→ ваша функция
```

Проверьте, что включена настройка:

```text
Публичная функция
```

Если функция не публичная, Telegram не сможет отправить туда webhook-событие.

---

## 5.3. Скопировать URL функции

На странице Cloud Function найдите URL вызова.

Он выглядит примерно так:

```text
https://functions.yandexcloud.net/xxxxxxxxxxxx
```

Сохраните его:

```env
FUNCTION_URL=https://functions.yandexcloud.net/xxxxxxxxxxxx
```

Этот URL понадобится для настройки webhook.

## 5.4. Установить Telegram webhook

Откройте в браузере ссылку:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=<FUNCTION_URL>&allowed_updates=%5B%22message%22%2C%22callback_query%22%5D
```

Замените:

```text
<TELEGRAM_BOT_TOKEN>
```

на токен вашего Telegram-бота.

Замените:

```text
<FUNCTION_URL>
```

на URL вашей Cloud Function.

Пример:

```text
https://api.telegram.org/bot1234567890:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx/setWebhook?url=https://functions.yandexcloud.net/xxxxxxxxxxxx&allowed_updates=%5B%22message%22%2C%22callback_query%22%5D
```

Если всё прошло успешно, Telegram вернёт ответ:

```json
{
  "ok": true,
  "result": true,
  "description": "Webhook was set"
}
```

---

## 5.5. Почему важен `callback_query`

В ссылке используется параметр:

```text
allowed_updates=["message","callback_query"]
```

В URL-encoded виде:

```text
allowed_updates=%5B%22message%22%2C%22callback_query%22%5D
```

Важно, чтобы там был:

```text
callback_query
```

Именно `callback_query` отвечает за нажатия inline-кнопок.

Если webhook настроен только на:

```text
message
```

то обычные сообщения будут доходить до функции, но кнопка **«Принять заказ»** работать не будет.

## Шаг 6. Настройка YMQ Trigger для напоминаний

Этот шаг нужен только для **Pro-версии**.

В Lite-версии нет очереди, статусов и напоминаний, поэтому этот шаг можно пропустить.

---

## 6.1. Зачем нужен YMQ Trigger

В Pro-версии после получения нового заказа функция кладёт `request_id` в очередь Yandex Message Queue с задержкой.

Например:

```text
REMINDER_DELAY_SECONDS=600
```

`600` секунд = 10 минут.

Схема:

```text
Новый заказ
  ↓
Cloud Function отправляет уведомление в Telegram
  ↓
Cloud Function сохраняет заказ в YDB со статусом pending
  ↓
Cloud Function кладёт request_id в YMQ с задержкой 10 минут
  ↓
Через 10 минут YMQ Trigger запускает эту же Cloud Function
  ↓
Функция проверяет статус заказа в YDB
  ↓
Если status = pending → отправляет напоминание
Если status = accepted → ничего не делает
```

---

## 6.2. Проверить, что очередь уже создана

Перед созданием триггера должна быть готова очередь:

```text
insales-order-reminders
```

И должен быть сохранён её URL:

```env
YMQ_QUEUE_URL=
```

Пример:

```env
YMQ_QUEUE_URL=https://message-queue.api.cloud.yandex.net/xxxx/yyyy/insales-order-reminders
```

---

## 6.3. Проверить права сервисного аккаунта

Сервисный аккаунт должен иметь права на чтение очереди и запуск функции.

Минимально для этого шага нужны роли:

```text
ymq.reader
serverless.functions.invoker
```

Для всей Pro-версии обычно используются роли:

```text
ydb.editor
ymq.writer
ymq.reader
serverless.functions.invoker
```

Что важно:

| Роль | Зачем нужна |
|---|---|
| `ymq.writer` | функция кладёт сообщение в очередь |
| `ymq.reader` | триггер читает сообщение из очереди |
| `serverless.functions.invoker` | триггер может запускать Cloud Function |
| `ydb.editor` | функция проверяет и обновляет статус заказа |

Если напоминание не приходит, но уведомление о заказе приходит, часто не хватает именно роли:

```text
ymq.reader
```

## 6.7. Настройки группировки сообщений

Рекомендуемые настройки:

```text
Размер группы: 1
Время ожидания: 0 секунд
```

Это значит, что каждое сообщение из очереди будет отдельно запускать функцию.

Для напоминаний по заказам это удобно: один заказ — одно событие — одно напоминание.

## 6.8. Настройки повторных запросов

На первом запуске можно поставить:

```text

```

Так проще отлаживать интеграцию и не получать повторные напоминания при ошибке.

После проверки можно увеличить число попыток, например до:

```text
3
```
Но, как правило в этом нет никакой необходимости.

## 6.9. Dead Letter Queue

На старте DLQ можно не настраивать.

Оставьте:

```text
Очередь DLQ: не выбрана
```

DLQ можно добавить позже, если нужно отдельно сохранять сообщения, которые не удалось обработать.

## 6.10. Проверить задержку напоминания

```env
REMINDER_DELAY_SECONDS=600
```

Это значит:

```text
600 секунд = 10 минут
```

Для тестирования можно временно поставить:

```env
REMINDER_DELAY_SECONDS=60
```

После изменения переменной окружения нужно создать новую версию Cloud Function.

## 6.11. Проверить работу напоминания

Для проверки:

1. Создайте тестовый заказ или отправьте тестовое письмо.
2. Дождитесь сообщения о заказе в Telegram.
3. Не нажимайте кнопку **«Принять заказ»**.
4. Дождитесь времени из `REMINDER_DELAY_SECONDS`.

Ожидаемый результат:

```text

Заказ: №...

Клиент: ...
Телефон: ...

```

В текущей версии напоминание отправляется без кнопки и содержит только краткие данные клиента и ссылку на заказ.

---

## 6.12. Что происходит, если заказ уже принят

Если менеджер нажал кнопку:

```text
✅ Принять заказ
```

статус заказа в YDB меняется:

```text
pending → accepted
```

Когда через 10 минут сработает YMQ Trigger, функция проверит статус.

Если статус уже:

```text
accepted
```

напоминание не отправляется.

## 6.14. Частые проблемы

### Уведомление о заказе приходит, но напоминание нет

Проверьте:

```text
YMQ Trigger создан
Триггер привязан к правильной очереди

Сервисный аккаунт указан
У сервисного аккаунта есть ymq.reader
```

---

### В очереди есть сообщения, но функция не запускается

Проверьте роли сервисного аккаунта:

```text
ymq.reader
serverless.functions.invoker
```

Также проверьте, что в триггере выбрана именно та очередь, куда функция отправляет сообщения.

---

### Напоминание не приходит, потому что заказ уже принят

Это нормальное поведение.

Если статус заказа в YDB:

```text
accepted
```

функция не отправляет повторный пинг.

Для теста создайте новый заказ и не нажимайте кнопку принятия.

---

### Напоминание приходит слишком поздно или слишком рано

Проверьте переменную:

```env
REMINDER_DELAY_SECONDS=
```

Например:

```env
REMINDER_DELAY_SECONDS=600
```

Это 10 минут.

Для тестов можно использовать:

```env
REMINDER_DELAY_SECONDS=60
```

Но после тестирования лучше вернуть:

```env
REMINDER_DELAY_SECONDS=600
```

---

### Напоминание приходит с неправильным текстом

Текст напоминания находится в коде функции, в блоке, который формирует reminder-сообщение.

В Pro-версии напоминание специально сделано коротким:

```text
заказ
клиент
телефон
email
ссылка на админку
```

Состав заказа, сумма, оплата и кнопка принятия в напоминание не добавляются.

```json
  "ok": true,
  "result": {
    "url": "https://functions.yandexcloud.net/xxxxxxxxxxxx",
    "allowed_updates": [
      "message",
      "callback_query"
    ]
  }
}
```

Важно:

```text
url не должен быть пустым
allowed_updates должен содержать callback_query
```

Если `callback_query` нет, переустановите webhook:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=<FUNCTION_URL>&allowed_updates=%5B%22message%22%2C%22callback_query%22%5D
```

Также проверьте, что функция публичная и бот имеет право редактировать сообщения в чате или канале.

## 7.10. Проверить напоминание


## Шаг 8. Типовые ошибки и отладка

В этом разделе собраны частые проблемы, которые могут возникнуть при настройке интеграции.

---

## 8.1. Telegram-сообщение не приходит

Если письмо отправлено, но в Telegram ничего не пришло, сначала проверьте логи функции:

```text
Yandex Cloud
→ Cloud Functions
→ ваша функция
→ Логи
```

В логах должна быть строка:

```text
Route: email order
```

Если такой строки нет, значит функция не получила письмо.

Проверьте:

```text
Email Trigger создан
Email Trigger привязан к правильной функции
Выбран правильный тег версии функции
Письмо отправлено на email-адрес триггера
Сервисный аккаунт указан в триггере
```

---

## 8.2. Функция запускается, но Telegram молчит

Если функция запускается, но сообщение в Telegram не приходит, проверьте переменные окружения:

```env
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

Если используется тестовый чат:

```env
TELEGRAM_CHAT_ID_TEST=
```

Также проверьте:

```text
бот добавлен в нужный чат
chat_id указан правильно
бот не заблокирован
бот имеет право отправлять сообщения
```

Проверить отправку вручную можно через браузер:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/sendMessage?chat_id=<TELEGRAM_CHAT_ID>&text=Проверка
```

Если сообщение не приходит и через этот URL, проблема не в коде, а в Telegram-боте, токене или chat_id.

---

## 8.3. `getUpdates` возвращает пустой массив

Если при получении `chat_id` запрос:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

возвращает:

```json
{
  "ok": true,
  "result": []
}
```

проверьте:

```text
бот добавлен в чат
после добавления бота в чат было отправлено новое сообщение
у бота не установлен webhook
```

Если webhook уже установлен, временно сбросьте его:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/deleteWebhook
```

После этого отправьте новое сообщение в чат и снова вызовите:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates
```

---

## 8.4. Кнопка “Принять заказ” не работает

Если сообщение приходит, но кнопка не работает, проверьте Telegram webhook:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo
```

В ответе должно быть:

```json
{
  "ok": true,
  "result": {
    "url": "https://functions.yandexcloud.net/xxxxxxxxxxxx",
    "allowed_updates": [
      "message",
      "callback_query"
    ]
  }
}
```

Важно:

```text
url не должен быть пустым
allowed_updates должен содержать callback_query
```

Если `url` пустой, webhook не установлен.

Если в `allowed_updates` есть только:

```text
message
```

то кнопки работать не будут.

Переустановите webhook:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=<FUNCTION_URL>&allowed_updates=%5B%22message%22%2C%22callback_query%22%5D
```

## 8.5. Кнопка нажимается, но не меняется на “Принято”

Если после нажатия кнопки заказ принимается, но кнопка визуально не меняется, чаще всего у бота нет прав на редактирование сообщений.

Проверьте права бота в Telegram-чате или канале:

```text
Чат / канал
→ Управление
→ Администраторы
→ ваш бот
```

Для Pro-версии боту нужны права:

```text
отправлять сообщения
редактировать сообщения
```

Если используется канал, бот должен быть администратором канала.

---

## 8.6. В логах нет `Route: telegram callback`

После нажатия кнопки в логах функции должна появиться строка:

```text
Route: telegram callback
```

Если её нет, значит Telegram не отправляет callback в функцию.

Проверьте:

```text
webhook установлен
webhook установлен на правильный URL функции
allowed_updates содержит callback_query
функция публичная
используется тот же бот, который отправляет сообщения
```

## 8.7. `getWebhookInfo` показывает `pending_update_count`

Пример:

```json
{
  "pending_update_count": 17
}
```

Это значит, что Telegram накопил необработанные события.

Частые причины:

```text
webhook был сброшен
функция была недоступна
webhook указывал на неправильный URL
функция возвращала ошибку
```

Если после исправления webhook всё работает, старые события обычно можно игнорировать.

## 8.8. Ошибка `Cannot find module '@yandex-cloud/nodejs-sdk...'`

Если в логах ошибка вида:

```text
Cannot find module '@yandex-cloud/nodejs-sdk/dist/token-service/metadata-token-service'
```

значит в `package.json` не хватает зависимости:

```json
{
  "dependencies": {
    "@yandex-cloud/nodejs-sdk": "latest"
  }
}
```

Для Pro-версии `package.json` должен содержать:

```json
{
  "dependencies": {
    "ydb-sdk": "^5.11.1",
    "@yandex-cloud/nodejs-sdk": "latest",
    "@aws-sdk/client-sqs": "^3.600.0",
    "html-to-text": "^9.0.5"
  }
}
```

После изменения `package.json` создайте новую версию функции.

---

## 8.9. Ошибка подключения к YDB

Если функция падает при работе с YDB, проверьте переменные:

```env
YDB_ENDPOINT=
YDB_DATABASE=
```

Правильный формат:

```env
YDB_ENDPOINT=grpcs://ydb.serverless.yandexcloud.net:2135
YDB_DATABASE=/ru-central1/xxxx/yyyy
```

Неправильно:

```env
YDB_ENDPOINT=grpcs://ydb.serverless.yandexcloud.net:2135/?database=/ru-central1/xxxx/yyyy
```

`YDB_ENDPOINT` должен содержать только endpoint без `?database=...`.

```text
YDB_ENDPOINT указан правильно
```

## 8.14. Напоминание не приходит, потому что заказ уже принят

Это нормальное поведение.

Если менеджер нажал кнопку:

```text
✅ Принять заказ
```

статус в YDB меняется:

```text
pending → accepted
```

Когда через 10 минут срабатывает YMQ Trigger, функция проверяет статус. Если статус уже:

```text
accepted
```

напоминание не отправляется.

Для теста создайте новый заказ и не нажимайте кнопку.
